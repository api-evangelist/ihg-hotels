# IHG Hotels & Resorts

> InterContinental Hotels Group PLC (IHG Hotels & Resorts) is a British asset-light hotel group headquartered in Windsor, United Kingdom, with an Americas office in Atlanta, Georgia. Its corporate site reports 7,014 hotels and 1,035,589 rooms across more than 100 countries, around 400,000 colleagues, 20 brands and the IHG One Rewards loyalty programme. **IHG publishes no API.** There is no developer portal, no reference documentation, no machine-readable contract and no authentication scheme of any kind in the public domain as of 2026-07-28. This file is generated by API Evangelist from the catalogue record, not published by IHG.

## What an agent needs to know first

- **There is no IHG API you can call.** `apis[]` in the catalogue record is deliberately empty. Do not attempt to construct an IHG endpoint from a hostname — every real one is gated.
- Real API infrastructure exists and is closed. `api.ihg.com` CNAMEs to `ihg.api.mashery.com` (with an `sb-ihg.mashery.com` sandbox in the chain) and times out. `apis.ihg.com`, `dev-apis.ihg.com`, `mcp.ihg.com`, `booking.ihg.com` and `www.ihg.com` sit behind Akamai and return **403 Access Denied** on every path, including `/openapi.json`, `/swagger.json`, `/api-docs`, `/graphql` and `/.well-known/`. `concerto.ihg.com` (the internal hotel operating platform) returns **401**.
- There is **no** `/.well-known/security.txt`, no OpenID Connect discovery document, no RFC 8414 authorization-server metadata, no RFC 9727 api-catalog and no `ai-plugin.json` on any IHG host.
- There is **no** first-party MCP server. `mcp.ihg.com` resolves but its purpose is undocumented and is not assumed to be Model Context Protocol; `tools/list` returns 403.
- There is **no** first-party SDK, CLI or client library in any package registry.
- There is **no** public status page. `status.ihg.com` redirects to the hotel-owner intranet.
- There is **no** official IHG GitHub organisation, no APIs.guru entry and no SwaggerHub specification.

## The programme that was retired

IHG once ran a genuine public developer portal. **PartnerConnect RoomService** at `pcroomservice.ihg.com` was a TIBCO Mashery portal with self-service registration, an API key console with separate staging and production keys, an I/O Docs interactive console, an API gallery, a support forum and a published *IHG Commercial API Terms of Use*. It documented five APIs by name: Hotel Descriptive Info, Single Property Availability, Rate range (AREA availability), Hotel Search, and Single Property Availability with Rate Rules.

That portal is gone. `pcroomservice.ihg.com` is NXDOMAIN on Google, Cloudflare and Quad9 resolvers as of 2026-07-28; the Internet Archive holds page captures only through 2017. Search engines still index it and still describe it as operational — **that index is stale**. No successor, no migration guide, no redirect and no archive was published.

## How IHG inventory is actually reached programmatically

IHG does not run its own reservation platform. It partnered with **Amadeus** in 2015 to build a cloud Guest Reservation System replacing **HOLIDEX** (Holiday Inn's proprietary system, in service since 1965) and migrated across 2018 and early 2019; group and meetings bookings land in Amadeus Delphi and Meeting Broker. The documented routes to IHG rates and availability are therefore all third-party: Amadeus, Sabre, Travelport, Expedia Rapid/EPS, the Booking.com Demand API, and the bedbanks. None of them carries IHG's own commercial terms and none accrues IHG One Rewards points — that is only available through a direct commercial agreement with IHG, for which no application route, contact, pricing or eligibility criteria is published.
